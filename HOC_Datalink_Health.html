Troubleshooting reference

Connection: red, "Failed to fetch"

  • If running on https://hocoperations1.github.io/ → expected. Mixed-content block. Run from a datalink PC on http://localhost:8080 instead.
  • If running on http://localhost → check the Python web server is still running. Check that the terminal server is on the corporate network and can reach hoc-dts-svr-025:5555.

Connection: red, "HTTP 401" or "HTTP 403"

  • Vicinity OData requires authentication. The browser/RDP session needs to be running under a Windows account with Vicinity access.
  • Verify by opening http://hoc-dts-svr-025:5555/VicinityWeb/odata/HOCVIC/vv_Planning_Production%20Schedule?$top=1 directly in Edge — does it return JSON?

Pull succeeds but Supabase sync fails

  • Supabase URL/key may have changed. Run System Diagnostics to verify cloud connection.
  • Local cache (hoc_upload_v1) is still updated — tablets on the same datalink PC will see data. Other tablets won't until Supabase push recovers.

Some endpoints succeed, others fail

  • Normal — Vicinity may not have data in every view, or some views may require additional permissions.
  • Tier 1 endpoints (Production Schedule, Open Batches, Patch OEE, etc.) are the must-haves. Tier 2-5 are bonus.
